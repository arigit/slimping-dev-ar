OpenSubsonic Client Authentication

Controls which authentication schemes Subsonic clients (DSub, play:Sub, Symfonium, Tempo, Substreamer, etc.) may use to reach /rest/. Each scheme is independent — defaults are API key + token+salt, which is what most modern clients expect.

[% IF slimping_allow_plain_password %]
Plain password auth is enabled. Credentials travel essentially in the clear over the wire. Only enable this if a legacy client truly cannot do token+salt or API-key auth, and only on a network you fully trust.
[% END %] [% WRAPPER setting title="Auth Scheme: API Key" desc="Always available. The strongest scheme — credentials do not depend on stored plaintext passwords. Pass via the URL query parameter (?k=<key>) or the Authorization: Bearer header. Issue keys per-user in the Users accordion above. Ecosystem support is patchy as of 2026; check your client." %]
Always on (cannot be disabled).
[% END %] [% WRAPPER setting title="Auth Scheme: Token+Salt" desc="The Subsonic-standard scheme since v1.13 (md5(password+salt) on the wire, plaintext password stored server-side). What most popular clients actually use. Recommended on by default; only turn off if you are running an API-key-only deployment." %]
[% END %] [% WRAPPER setting title="Auth Scheme: Plain Password" desc="Legacy. Credentials travel essentially in the clear over the wire (the enc:hex variant is encoding, not encryption). Off by default. Only enable for old clients that cannot do token+salt — and prefer not to enable it at all if you can avoid it." %]
[% END %]
